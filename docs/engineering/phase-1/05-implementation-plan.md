# 任务 5：第一阶段实施计划

## 1. 阶段目标

建立可运行、可迁移、可测试、可部署的正式工程基础，并完成真实 MySQL 8 约束与事务验证。

第一阶段不交付：

- 完整商品管理。
- 顾客点单和桌位二维码业务。
- 完整库存与财务 API。
- 经营分析页面。
- 优惠业务。
- 真实微信支付。

## 2. 实施顺序

```text
P1-01 工具链与工作区
  -> P1-02 MySQL 8 与迁移基线
  -> P1-03 NestJS 基础设施
  -> P1-04 身份与权限基础
  -> P1-05 事务验收内核
  -> P1-06 真实 MySQL 约束测试
  -> P1-07 多连接并发测试
  -> P1-08 Web/小程序骨架
  -> P1-09 部署、文档与阶段验收
```

P1-05 到 P1-07 是相互依赖的核心验收链，不能用单纯 mock 通过。

## 3. 可独立验收任务

### P1-01 工作区与工具链

交付：

- npm workspace 根配置。
- Node 22 `.nvmrc` 和 `engines`。
- TypeScript 基础配置。
- lint/format/test 根脚本。
- `.gitignore`、`.env.example`。
- 统一依赖版本锁定。

验收：

1. Node 22 下 `npm ci`、`npm run build`、`npm test` 可执行。
2. 不依赖全局安装的 Nest CLI/Prisma CLI。
3. 密钥文件不入库。
4. 锁文件已提交。

状态：未开始。

### P1-02 MySQL 8 与迁移基线

交付：

- `docker-compose.yml` 的 MySQL 服务。
- 固定镜像 digest。
- 开发库和测试库初始化。
- `backend/prisma/schema.prisma`。
- 首版初始迁移。
- 补充约束迁移。
- 数据库启动/就绪/清理脚本。

验收：

1. 空库 `prisma migrate deploy` 成功。
2. SQL 约束、生成列、触发器全部创建。
3. 第二次部署 migrate 为 no-op。
4. 实际版本、`sql_mode`、隔离级别记录到验证报告。
5. 失败时不得写成通过。

状态：设计完成，未执行。当前 Docker daemon 不可用。

### P1-03 NestJS 基础设施

交付：

- NestJS 应用。
- `/api/v1` 前缀。
- 配置校验。
- PrismaService。
- 全局 ValidationPipe。
- 全局异常过滤。
- 统一成功响应。
- Request ID。
- 结构化日志。
- BigInt/Decimal 序列化。
- `/health/live`、`/health/ready`。

验收：

1. `ready` 在数据库不可用时返回非 200，数据库恢复后返回 200。
2. 参数校验失败返回稳定错误结构。
3. 日志包含 requestId，不泄露 token/OpenID。
4. BigInt 和 Decimal 响应格式有单元测试。
5. 未捕获异常不被静默吞掉。

状态：未开始。

### P1-04 身份与权限基础

前置确认：

- 员工登录方式。
- 初始 OWNER 账号创建流程。
- 微信 AppID/Secret 环境变量。

交付：

- WeChat 顾客登录入口。
- 员工登录入口。
- 密码/凭据安全哈希。
- JWT 签发与校验。
- RolesGuard。
- 资源归属 Guard。
- Store 单实例上下文。
- 角色/权限测试。

验收：

1. 前端伪造 `userId/storeId/role` 不影响服务端身份。
2. 顾客不能查询其他顾客订单。
3. 非员工不能调用员工接口。
4. 停用的 Staff 不能继续使用旧 token。
5. OpenID 不出现在无权响应和普通日志中。
6. 没有假登录旁路或 debug 后门。

状态：未开始，存在认证方式待确认。

### P1-05 事务验收内核

范围：

- 只实现数据库验收所需的真实事务服务。
- 不实现完整业务 UI 和全量 API。

交付：

- DiningTable 行锁和活动桌单创建/复用。
- 多材料库存预占和全事务回滚。
- Idempotency claim/response 同事务。
- Payment 分次登记上限校验。
- Refund 原收款锁和累计退款上限。
- 固定锁顺序辅助层。
- 错误码：冲突、库存不足、额度不足、状态非法。

验收：

1. 事务代码必须通过 Prisma/MySQL 运行。
2. 不允许用进程内 mutex 替代数据库行锁。
3. 失败后业务表、库存流水和幂等记录均无部分提交。
4. 单元测试只覆盖纯计算；核心结论来自真实数据库集成测试。

状态：未开始。

### P1-06 真实 MySQL 约束测试

交付：

- C01-C15 数据库约束测试。
- 失败错误码/触发器消息断言。
- 数据变化前后查询。
- `database-verification.md`。

验收：

1. 每条约束测试命中指定约束，不把任意失败当作通过。
2. 失败后无部分写入。
3. 所有测试运行在独立 `_test` 数据库。
4. 版本、迁移输出、约束查询和测试结果均有证据。

状态：未执行。当前无 MySQL 8 环境。

### P1-07 多连接并发测试

交付：

- T01-T12 并发测试。
- 至少 20 个独立连接。
- 锁等待、冲突、回滚证据。
- 关键行变更前后快照。

验收：

1. 不使用单进程串行调用冒充并发。
2. 每个场景断言最终事实数量。
3. 同桌仅一个活动桌单。
4. 库存、收款、退款不重复且不超限。
5. 关闭桌单与新订单严格串行。
6. 失败请求返回明确 409/422 或领域错误，不静默吞掉。

状态：未执行。

范围：

Mini-program 交付：

- 微信原生小程序 + TypeScript。
- App/page 配置。
- API client。
- 登录会话初始化页。

验收：

1. 两端均不包含 localStorage 业务真源。
2. API base URL 通过环境配置。
3. 401、网络失败、超时有统一处理。
4. 只调用已存在的后端健康/认证接口。
5. 不出现大量 TODO Controller 或假数据业务闭环。
