# 任务 5：第一阶段实施计划

## 1. 阶段目标

建立可运行、可迁移、可测试、可部署的正式工程基础，并完成真实 MySQL 8 约束与事务验证。

第一阶段不交付：

- 完整商品管理。
- 顾客点单和桌位二维码业务。
- 完整库存与财务 API。
- 经营分析页面。
- 优惠业务。
- 真实微信支付。

## 2. 实施顺序

```text
P1-01 工具链与工作区
  -> P1-02 MySQL 8 与迁移基线
  -> P1-03 NestJS 基础设施
  -> P1-04 身份与权限基础
  -> P1-05 测试专用最小事务验证
  -> P1-06 真实 MySQL 约束测试
  -> P1-07 独立连接并发与压力测试
  -> P1-08 Web/小程序骨架
  -> P1-09 部署、文档与阶段验收
```

P1-05 到 P1-07 是相互依赖的核心验收链，不能用单纯 mock 通过。

### P1-05 测试专用最小事务验证

范围：

- 不实现一套与后续正式业务服务重复的“事务内核”。
- 在 `tests/database/transaction-harness` 实现最小事务测试夹具。
- 测试夹具不进入生产运行依赖、不暴露 API、不作为后续业务服务复用实现。
- 正式订单、库存、收款和桌单服务在后续对应阶段实现。

必须覆盖：

- 同桌首单并发。
- 库存预占与整事务回滚。
- 幂等请求。
- 收款金额上限。
- 退款额度竞争。
- 桌单关闭与新订单并发。
- 桌单关闭前置条件。

验收：

1. 测试代码必须连接真实 MySQL，不使用内存数据库。
2. 不允许用进程内 mutex 替代数据库行锁。
3. 失败后业务表、库存流水和幂等记录均无部分提交。
4. 并发测试保留最终数据库状态断言。
5. 测试通过的锁顺序和事务模式写入验证报告，供后续正式业务实现复用。
6. 不在 `backend/src` 创建生产业务服务空壳。

状态：未开始；依赖真实 MySQL 8 环境。

### P1-07 独立连接并发与压力测试

交付：

- T01-T09 普通竞态测试。
- S01-S05 桌单关闭规则测试。
- P01 库存预占 100 请求压力测试。
- 同步屏障工具。
- 锁等待、冲突、回滚证据。
- 关键行变更前后快照。

执行规则：

- 普通竞态使用 2～5 个独立数据库连接。
- P01 使用 100 个独立请求/连接，在同一同步屏障后并发执行。
- 所有并发测试必须真实连接 MySQL，不能用单线程循环冒充并发。
- 每个测试结束后读取数据库最终状态，而不是只检查 Promise 返回值。

验收：

1. 同桌仅存在一个活动桌单。
2. 库存、收款、退款不重复且不超限。
3. 存在未完成订单时关桌失败。
4. 存在净未结金额时关桌失败。
5. 已结清后允许关闭，并清除桌位 activeSessionId。
6. 关闭与新订单并发时不产生非法状态。
7. 100 请求库存预占后无负库存、无部分流水、成功数与 reserved 增量一致。
8. 失败请求返回明确 409/422 或领域错误，不静默吞掉。

状态：未执行，依赖真实 MySQL 8 环境。

## 6. 风险与阻塞项

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| Docker daemon 不可用 | P1-02 之后无法执行 MySQL 8 迁移和测试 | Gate 0 不阻塞；Gate 2 前必须修复 |
| Node 当前为 24，目标是 22 | 运行时偏差 | P1-01 固定 `.nvmrc` 和 engines |
| 员工认证方式未确认 | 无法冻结 StaffCredential | P1-04 前确认，不阻塞 P1-01/P1-02/P1-03 |
| 微信 AppID/Secret 未提供 | 无法做真实微信登录集成 | 骨架可用环境变量占位，登录验收后置 |
| 测试夹具误变生产服务 | 形成重复业务逻辑 | 测试目录隔离，正式服务后续按域实现 |
| 100 并发连接超过 MySQL 上限 | 压力测试不稳定 | 测试环境提高 `max_connections` 并记录配置 |
| MySQL DDL 非事务性 | 迁移失败可能留下半初始化 Schema | 删除并重建测试库后重跑，不继续使用失败库 |
